01 — THE COMPLAINTWhat you actually said

the tool is buggy graphically it is bad and the side bar (the queue was removed) lavish was much better

All three parts were true, and the third turned out to explain the first two.

I built it, served the demo artifact, drove it in a real browser, and ran lavish beside it on the same page. Three defects reproduced with measurements — and one structural cause sitting underneath them.

src/sdk/cards.ts — positionAt

Cards rendered off-screen. The clamp handled the two overflow cases — a card extending past the bottom or right edge — and neither of the near edges. An element scrolled above the fold has a negative rect.top, which passes an overflow test untouched. A real card measured top: -482px at 313px tall: entirely invisible. You clicked Explain and nothing happened. Both axes now clamp on both sides.

src/daemon/server.ts — handleOpenSession, the shell

And the reason there was no sidebar. The shell served an iframe at position:fixed;inset:0. The artifact owned the entire viewport, so a persistent column could not exist — every piece of review UI had to be drawn inside the sandboxed artifact as corner-pinned toggles and floating boxes. The shell is a three-area grid now: bar, stage, rail.

02 — THE TELLSix comments saying the same thing

The chrome client carried this sentence in six places: "no chrome-shell UI exists yet to surface this to." A failed dispatch, a failed sync, a superseded load, a degraded staleness watcher — all best-effort, all silent, all deferring to a surface nobody had built. That surface is the rail.

src/chrome/rail.ts — createRail

Review, Findings and Agent tabs, and the queue. It owns no network and no postMessage — every side effect leaves through a callback, so the chrome client keeps its position as the only place an HTTP call is ever made. Card prose is model output arriving from a sandboxed frame, so it is assigned by textContent only, never innerHTML — the same invariant the in-artifact renderer holds. Its own composer is gone: notes are written on the element now, so what stays in the footer is the one genuinely rail-shaped action — flushing the whole queue at once.

src/chrome/chrome-css.ts — CHROME_CSS

The old chrome was not bad because it was hand-written. It was bad because it had no scale to be consistent with: one grey, one blue, 11px system-ui throughout. There is a token layer now — surfaces, four ink steps, one accent, semantic state, a 4px space ramp, two motion durations — and the artifact stylesheet mirrors its values so a card and the rail beside it stop reading as two different products. Nothing here may reference a remote URL: the zero-outbound-request export proof covers this document too.

src/shared/intent.ts — TypedIntentPayload.note

The obvious shortcut was to reuse learnerNote, which already existed on the wire. It would have been wrong in a way nothing would have reported: a learnerNote is the reader's own explanation, and its presence switches the envelope to the grading contract. Every note you typed would have been silently submitted to be marked. A note is payload carried by a typed intent — it never selects the role, the tier or the tools, and a test proves that against a note that tries to.

src/cli/output.ts — renderPollResult

The gap that mattered most was not visual. The composer wrote a note, the wire carried it, the envelope kept it — and this renderer printed id, role, tier, intent and source, and not the note. An agent polling for work saw explain src/foo.ts:1-20 and none of what had been asked. Whatever this function omits does not exist as far as that agent is concerned. The note, the learner's explanation and the path of every attached image all print now, in full, under distinct labels.

src/sdk/follow-up.ts — buildFollowUpPayload

Suppressing the floating card made Go deeper and Check my understanding unreachable — a regression I introduced and had to find. The rail cannot build those payloads itself: a follow-up must be grounded in the element as it reads now, and the rail holds only the stored snapshot, which is by definition what the artifact said earlier. So the rail asks the artifact to run the action, and this is the single construction both paths use.

04 — THE THREE OLD DEFECTSClosed in parallel

src/daemon/state-dir.ts — canonicalPathKey, statePathHash

illuminate stop .demo printed "not running" while the daemon kept listening. Three modules each had their own copy of "lower-case the raw string, hash it", so every spelling but one hashed to a key no daemon had written. One canonical form now, and a file argument resolves to its directory. No migration was needed and that is provable: canonicalization is a fixed point for the derivation the working path already used.

src/daemon/dispatch-ledger.ts — enqueueDispatch

A failed dispatch used to poison its element and intent permanently: the entry stayed open, dedupe matched against it, and every retry was a silent no-op — even after the original cause was fixed. A retry now re-opens a dispatch that has no answer and nothing working on it, keeping the existing id. Age-based expiry was rejected: age is a guess, "nothing is listening and nothing came back" is a fact.

src/daemon/state-gc.ts — the sweep

The state directory had grown to 238 files with nothing ever removing them. A pair is deleted only when the daemon is provably dead, no artifact named by any session still exists, and the newer file is past a minimum age. Liveness is a pid check, never a socket — garbage collection must not connect to an arbitrary port it found on disk. 238 files became 5 on the first run.

06 — HONESTYThree things I got wrong on the way

The build was broken and the tests were green. A CSS comment inside the artifact stylesheet used backticks — inside a template literal, which ended the stylesheet mid-rule. esbuild failed loudly, but npm run build | tail -1 reports tail's exit status, so every gate chained after it passed against a stale dist. Found by taking a screenshot, not by running anything.

I made an existing test vacuous. The rail renders a pending row and a real answer with the same class, told apart by a data attribute. A spec that waited for .il-card to prove a card stops saying "thinking…" now matched the placeholder already on screen and passed instantly.

I animated a fact. The staleness marker's fill was in a CSS transition, so a computed-style read could land mid-interpolation — 0.337 against a declared 0.35. Hover and focus may ease; a marker appearing is information, and delaying it is not a flourish.
