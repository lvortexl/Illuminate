01 — THE PROBLEMWhy this exists

An agent writes you a beautiful architecture document. Three months later it says index.ts holds the IPC handlers at lines 1030–1200. The file is 288 lines. Nothing errors. The document just quietly became fiction.

A confidently stale diagram is worse than no diagram, because it spends trust it has not earned. illuminate's wager is that a document should be able to check itself against the code it describes — and say so, quietly, when it no longer matches. This page is that wager taken literally.

02 — SHAPEThree processes, one direction

illuminate is an AXI: a plain CLI any agent harness can drive. Not an MCP server, not a library you embed. It serves your artifact, watches for clicks, resolves the provenance behind whatever you clicked, and emits a fully-provisioned envelope. Your harness does the dispatch. illuminate itself never calls a model API.

The crucial detail is the sandbox. The artifact runs in an iframe with no allow-same-origin, so it cannot reach the server at all. Every request is made by the chrome shell, after the artifact asks it to via postMessage.

src/sdk/post.ts — the entire file

That postMessage boundary has exactly one call site in the whole source tree, and a regression test walks all of src/ to prove it stays that way. All three public actions — posting a typed intent, dismissing a staleness finding, and telling the chrome rail which element you just pointed at — funnel through one private send. A second call site would be a second place to get the target origin wrong.

src/html/inject.ts — injectScriptTag

The bytes illuminate serves differ from your file on disk by exactly one script tag. It is spliced in at a byte offset, never re-serialized: the HTML is parsed only to locate the real closing body tag, and a source-text test asserts parse5.serialize() appears nowhere in the codebase. Rebuilding HTML from a parse tree silently mutates ordinary markup, which would break the promise that what you see served is what you saved.

03 — SPINEThe four things that must not bend

These are enforced by tests, not by convention. Each is a property the system would lose silently if someone refactored carelessly, so each has a test whose only job is to fail loudly at that moment.

src/shared/intent.ts — the closed intent set

Intent is typed at the browser, not inferred from text. Five values, closed: explain, verify, deeper, fix-artifact, fix-code. This is the boundary furthest from any model output, which is what makes the next invariant possible at all.

src/router/policy.ts — POLICY_TABLE, resolvePolicy

Model output can never select a role or tier. The router is a pure lookup table keyed on that typed intent. resolvePolicy takes one argument and branches on nothing. An adversarial SYSTEM: directive embedded in resolved source rides through verbatim and moves neither the role nor the model tier — there is structurally nothing here for it to influence.

src/provenance/confine.ts — confineToRepoRoot

Path containment is the real security boundary. A data-src is untrusted — it was authored by an agent regenerating a document. realpathSync resolves symlinks and junctions before the containment check, so an escaping symlink is caught by the filesystem rather than missed by a string-prefix comparison. This function is also, as section 06 explains, the cause of the one real gap in the build.

src/daemon/poll.ts — the long-poll contract

Answers never enter the orchestrating agent's context. The poll response carries envelopes and receipts — never answer prose. This is proven on the wire rather than by inspection: a test ingests twenty uniquely-marked answers and greps the raw response bytes for all twenty, with a positive control on a different route so the negative cannot pass vacuously.

04 — PROVENANCEHow an element earns an explanation

An element is grounded when it cites its source. data-src gives a repo-relative path and optional line range; data-rev pins a commit, or is omitted to resolve against HEAD as unpinned; data-anchor-hash fingerprints the content that was there when the claim was written.

src/provenance/hash.ts — normalizeAnchorRegion

That fingerprint normalizes line endings and trailing whitespace, and nothing else — interior whitespace and indentation are deliberately significant, so a region re-indented from two spaces to four hashes differently and is correctly reported as touched. This is the single normalization boundary in the codebase; a second line-ending regex anywhere in src/provenance/ would quietly desynchronize the whole staleness model.

src/provenance/drift.ts — classify, the four-state ladder

Drift resolves down a ladder rather than to a boolean. Content that moved within a file is moved and still resolvable; content that changed is touched; content that can no longer be found is lost. Ambiguity resolves downward — a region that might have moved is reported as the more cautious touched, never guessed into a confident wrong answer.

05 — DURABILITYSurviving reloads, restarts, and Windows

src/store/async-mutex.ts — AsyncMutex

Cards and findings live in JSON sidecars that several concurrent request handlers read-modify-write. Twenty-five simultaneous mutations each adding a uniquely-keyed record must all land — so every write serializes through one in-process mutex, and writes are atomic renames that retry on Windows EPERM. A reader observes either fully-old or fully-new content, never a torn file.

src/daemon/spawn.ts — spawnDaemon

This is where the project's worst bug lived, and it is worth reading as a cautionary tale. Node's canonical daemon example uses detached: true, which on Windows hands the child a visible console window. To avoid that flash, win32 was given detached: false — which quietly tied the daemon's lifetime to the CLI that spawned it. Running illuminate <file> printed a healthy URL and the daemon died the instant the CLI exited.

The two requirements were never in tension. windowsHide sets CREATE_NO_WINDOW and is what suppresses the console; detached governs lifetime, not visibility. The docs' example flashes a window because it omits windowsHide, not because it sets detached.

test/daemon/spawn.test.ts — parent-exit survival

Why it survived nine phases of review: this test called t.skip whenever the child did not survive, reasoning that a non-surviving child proved a hardened host policy rather than a defect. It was vacuous on precisely the condition it existed to detect — and the rationalisation propagated, becoming a confident claim across several planning documents that this machine kills detached children and only CI could ever judge the requirement. None of it was true. Removing the guard dropped the suite's skip count from four to one and turned three vacuous tests into real ones.

src/daemon/state-dir.ts — stateDir

Lockfiles and session records go to the OS state directory — LOCALAPPDATA on Windows, Application Support on macOS, XDG_STATE_HOME on Linux — and a missing environment variable fails loudly rather than scattering state somewhere plausible. This file's own comment — illuminate never writes state next to the user's artifact — was quietly false until today, because the findings sidecar sat beside the artifact. Section 06 is where that got resolved.

06 — OPENWhat is not finished

Two of the three open decisions are closed and implemented, and the requirement thought to need CI turned out to be a real bug that is now fixed. What is left is three checks no test can settle, and one call that is yours alone.

The deleted-file gap — fixed

Closed 2026-09-17 — STAL-03

Until today, resolve() could not classify a genuinely deleted cited file as lost through its public entry point — the single most important case staleness exists to catch. The cause sat upstream of staleness entirely: parseAnchor called confineToRepoRoot unconditionally, a deleted file made realpathSync throw, and any unresolvable path was treated as a security refusal. The lost branch in drift.ts was correct, tested, and structurally unreachable.

src/provenance/confine.ts — realpathAllowingMissingTail

Containment now walks to the nearest existing ancestor, resolves that, and appends only the provably-absent tail. Security is unweakened by construction: every segment that exists is still symlink-resolved before the comparison, and a path component that does not exist cannot itself be a symlink, so appending it cannot escape the prefix just resolved. A missing path traversing outside the root — and a missing leaf underneath an escaping junction — are both still refused.

The proof runs at all three levels the gap analysis said it did not: 4 new containment tests, 3 new integration tests (the first in this codebase at any phase to assert lost through the real resolve()), and the browser lifecycle spec — whose deletion step no longer seeds the finding. A real deletion, detected by the real live scanner, rendered in a real browser.

Where sidecars live — split, done

Closed 2026-09-17

Both sidecars used to sit beside your artifact, which is the thing state-dir.ts says illuminate never does. They now split along what they actually are.

src/store/annotation-store.ts — annotationStorePathFor

The .illum.json sidecar holds your cards — answers, your own written explanations, verification verdicts. These are yours and are not reproducible; if you copy the artifact elsewhere they must come with it. Unchanged: it stays beside the artifact.

src/store/findings-store.ts — findingsStorePathFor

Staleness findings are derived — a rescan rebuilds them from scratch — so they were clutter in your directory that did not need to travel. They now live in the state directory, keyed through state-dir.ts's single statePathHash — one canonical form of the path, lower-cased, so NTFS cannot split one artifact across two files and no two spellings of the same directory can address two different daemons.

Publication

Decided: hold until validated

A publish branch exists: one orphan commit, 207 files, verified to build and pass the full suite on its own, with no planning documents and no history. The orphan shape is deliberate — an earlier phase used a private repository as its test corpus, and that content is in master's history where scrubbing cannot reach it. Re-verified clean of both planning files and private-path leaks.
